v0.2.0 검증
- 실제 앱(Linux, 가상 화면): 잠금 상태 시작 → 틀린 암호 거부 → 맞는 암호로 해제 → 암호화된 기록 표시 → 1분 무사용 후 **자동 잠금** 확인. 저장 파일에 기록 원문 없음, 키는 `pass:v1` 형식.
- 실제 앱: Rust가 띄운 파일 선택 창으로 CSV를 불러와 통계 계산 확인.
- 실제 GitHub: 업데이트 확인 → 공개 릴리스(v0.1.0-beta.1) 발견 → Windows 설치 파일(6,806,202바이트) 내려받기 → SHA-256 일치 확인. 감사 기록에는 GitHub 호스트만 남음.
- 자동 테스트: 단위 77, 통합 11, 한국어 PDF 1, 정적 보안 7, 앱 1. 보안 스크립트 5/5(차단 공간에서 테스트 전체 통과, 외부 연결 시도 없음).
- 미검증: Windows·macOS에서 화면 캡처 방지·키체인 잠금·Job Object의 실제 동작, 실제 AI 모델 응답.

## 1. 결론
- 앱 코드 수준의 개인정보 외부 전송 통제는 **자동 테스트로 확인**되었습니다.
- 실제 Ollama 엔진(v0.40.16, 공식 배포 파일)으로 **설치 무결성·클라우드 차단·루프백 전용 실행·프로세스 정리**를 확인했습니다.
- 다만 **실제 AI 모델을 내려받아 실행하는 단계는 검증하지 못했습니다**(개발 환경에서 모델 저장소 registry.ollama.ai 접근 차단).
  Windows·macOS에서의 **실행** 검증도 없습니다(빌드만 CI에서 수행).
- 따라서 **공개 배포 전 7절의 남은 검증을 반드시 수행**해야 합니다.

## 2. 위협과 통제 (요약 — 상세는 SECURITY_MODEL.md)
1. 앱이 자료를 외부로 보냄 → HTTP 클라이언트는 `security/netguard.rs`에서만 생성(정적 검사로 강제). 추론 요청은 `http://127.0.0.1` IP 리터럴만, 프록시 미사용, 리다이렉트 미추종.
2. 화면(웹뷰)이 외부 접속 → CSP `default-src 'self'`, `connect-src ipc:`. AI 답변의 링크·이미지·HTML은 표시만 하고 열지 않음.
3. 엔진 클라우드 기능 → `OLLAMA_NO_CLOUD=1` 강제 + 실행 후 `/api/status` 확인 + 클라우드 모델 이름·원격 응답 차단 + 앱 카탈로그 모델만 내려받기.
4. 엔진의 네트워크 노출 → `OLLAMA_HOST=127.0.0.1:<임의 포트>` 강제, 사용자 환경의 `OLLAMA_*` 제거, 외부 주소 접속 시도로 검증.
5. 변조된 엔진 → 버전·SHA-256 고정, 불일치·미등록 시 설치 거부, 압축 경로 탈출 차단.
6. 저장 자료 유출 → 필드 단위 XChaCha20-Poly1305, 키는 OS 키체인, SQLite secure_delete, 불러온 문서는 메모리만.
7. 로그 유출 → 앱 로그 파일 없음, 엔진 출력 폐기, 오류 문자열 개인정보 가림.
8. 프롬프트 인젝션 → 자료 구분자 위조 무력화, 모델에 도구·네트워크 권한 없음.
9. 앱 비정상 종료 후 엔진 잔존 → Linux PDEATHSIG, Unix 종료 신호 처리, Windows Job Object, 다음 실행 시 PID 검증 후 정리.

## 4. 실제 Ollama 검증 상세 (`crates/core/tests/real_engine.rs`)
- 공식 `ollama-linux-amd64.tar.zst`(1,545,767,640 바이트) 내려받기 → SHA-256 `87bfafb2…f9b`가 공식 `sha256sum.txt`와 일치 → 설치
- 동의 없이 설치·모델 내려받기 시도 → 거부(ConsentRequired)
- 엔진 버전 보고 `0.40.16`, `cloud.disabled = true`
- 종료 후 포트 닫힘·프로세스 없음

## 5. 실제 앱(Tauri) 검증 (Linux, 가상 화면)
- 창 표시·한국어 글꼴 렌더링 확인
- 창 닫기 / SIGTERM / SIGKILL 세 경우 모두 엔진 프로세스가 남지 않음

## 6. 알려진 한계
- 엔진 프로세스 자체의 외부 통신을 운영체제 방화벽으로 막지는 않습니다(모델 내려받기에 필요). 대신 클라우드 기능 꺼짐을 실행 중에 검증합니다.
- 다운로드 TLS는 OS 인증서 저장소를 신뢰합니다(기관 TLS 검사 프록시 호환). 엔진 파일 무결성은 SHA-256 고정으로 별도 보장되나, **모델 파일 무결성은 Ollama의 sha256 digest 검증에 의존**합니다.
- Linux의 키 파일 저장 방식은 OS 키체인보다 약합니다(Linux는 정식 지원 대상 아님).
- 사용자가 저장한 Word/Excel 결과물은 암호화되지 않습니다.
- Linux PDEATHSIG는 엔진을 시작한 스레드 기준으로 동작합니다(앱의 비동기 작업 스레드는 앱 수명 동안 유지되므로 실사용에는 영향 없음).
- Windows Job Object 코드는 Windows CI에서 컴파일되지만 **실제 강제 종료 동작은 미검증**입니다.

## 7. 배포 전 남은 검증
1. 네트워크가 허용된 환경에서 실제 모델(`gemma3:4b` 등) 내려받기 → 인터넷을 끊고 채팅·PDF·Excel 보고서 생성.
2. 실제 모델로 프롬프트 인젝션 문서 시험(답변이 외부 URL 접속·지시 수행을 권하지 않는지).
3. Windows 10/11, macOS(Apple 칩·Intel)에서 설치 → 실행 → 강제 종료 시 엔진 정리 → 제거.
4. Windows/macOS에서 `netstat`/`lsof`로 엔진이 127.0.0.1에만 열려 있는지 확인.
5. 코드 서명(Windows) 및 Apple 공증.
